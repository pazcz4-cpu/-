# המסלול: מה לעשות כשהתשובות מגיעות

שישה שלבים. השלב הקובע הוא 4 — עד שהוא עובר, `PAYPLUS_READY`
נשאר כבוי ושום כרטיס אינו מחויב.

---

## 1 · לקבל את פרטי הגישה

מלוח הבקרה של PayPlus, בסביבת הבדיקות:

| מה | איפה בדרך כלל |
|---|---|
| `api-key`, `secret-key` | הגדרות → מפתחות API |
| `payment_page_uid` | דפי תשלום → הדף שהוגדר לנו |
| `terminal_uid` | מסופים |

אם לא ברור איפה — זו שאלה 1 במכתב, שיפנו אותך.

> **לא שולחים לי אותם.** לא בצ'אט, לא בקובץ, לא בקומיט. הם
> נקראים בלוח הבקרה ומודבקים ישירות למקום שבו הם צריכים לשבת.
> אני כתבתי את הקוד שקורא אותם ממשתני סביבה; אני לא צריך לראות
> את הערכים כדי שהוא יעבוד.

## 2 · להריץ את בדיקת העשן — מהמחשב שלך

**זה חייב לרוץ אצלך.** לסביבה שבה אני עובד אין גישה לרשת של
PayPlus (`CONNECT tunnel failed, response 403`), ולכן אני לא יכול
להריץ את זה בעצמי — גם לא עם המפתחות.

מושכים את הקוד ומריצים:

```bash
git clone https://github.com/pazcz4-cpu/-.git setshifts
cd setshifts
git checkout claude/employee-shift-scheduling-n3lbhl

PAYPLUS_SANDBOX=true \
PAYPLUS_API_KEY='...' \
PAYPLUS_SECRET_KEY='...' \
PAYPLUS_PAYMENT_PAGE_UID='...' \
PAYPLUS_TERMINAL_UID='...' \
PUBLIC_BASE_URL=https://setshifts.com \
node tools/payplus-smoke.js
```

הכלי אומר בקול אם הפנית אותו בטעות לייצור, ואינו מדפיס אף מפתח.

---

## 3 · להזין כרטיס בדיקה

הכלי מדפיס כתובת של דף תשלום אמיתי בסבידת הבדיקות. פותחים אותה
בדפדפן ומזינים את כרטיס הבדיקה שקיבלת (שאלה 2 במכתב).

מההודעה החוזרת — או ממסך העסקאות בלוח הבקרה — לוקחים את הטוקן
ומריצים שוב:

```bash
PAYPLUS_SANDBOX=true PAYPLUS_API_KEY='...' PAYPLUS_SECRET_KEY='...' \
PAYPLUS_PAYMENT_PAGE_UID='...' PAYPLUS_TERMINAL_UID='...' \
node tools/payplus-smoke.js --token='...' --amount=1
```

עכשיו הוא בודק גם את החיוב מהטוקן וגם את האימות מול `ipn-full`.

## 4 · לשלוח לי את הפלט

**את הפלט של הכלי כן אפשר לשלוח לי** — הוא לא מכיל מפתחות, לא
מספרי כרטיס ולא טוקנים (הם מודפסים כאורך בלבד). זה בדיוק מה
שאני צריך:

- אם הכל עבר — אני מאשר, ואפשר להדליק.
- אם משהו נכשל — בפלט כתוב מה בדיוק חזר מ-PayPlus, ואני מתקן
  לפי זה. זה הדבר היחיד שאני עדיין לא יכול לדעת מכאן.

אם אתה מעדיף לא להריץ דרך הטרמינל — תשובה בכתב מהם לשאלה 4 במכתב
(נתיב החיוב מטוקן ושמות השדות) מספיקה לי באותה מידה.

## 5 · להגדיר את משתני הסביבה ב-Vercel

Settings → Environment Variables. הערכים מודבקים ישירות מלוח
הבקרה של PayPlus:

| Name | Value |
|------|-------|
| `BILLING_PROVIDER` | `payplus` |
| `PAYPLUS_API_KEY` | מלוח הבקרה |
| `PAYPLUS_SECRET_KEY` | מלוח הבקרה. חותם גם על ההודעה החוזרת |
| `PAYPLUS_TERMINAL_UID` | מלוח הבקרה |
| `PAYPLUS_PAYMENT_PAGE_UID` | מלוח הבקרה |
| `PAYPLUS_CASHIER_UID` | רק אם יענו שהוא נדרש |
| `PAYPLUS_INVOICES` | `true` רק אחרי שאושר שמודול המסמכים פעיל |
| `PUBLIC_BASE_URL` | `https://setshifts.com` |
| `CRON_SECRET` | מחרוזת אקראית שתמציא |
| `PAYPLUS_READY` | **רק אחרי שהכלי עבר** |

`PAYPLUS_SANDBOX=true` כל עוד בודקים; מסירים אותו כשעוברים לייצור
עם מפתחות הייצור — הם אינם אותם מפתחות.

ואצל PayPlus צריך להגדיר את כתובת ההודעה החוזרת:

```
https://setshifts.com/api/billing/webhook
```

## 6 · ייצור

חוזרים על 1–3 עם מפתחות הייצור, ורק אז מסירים `PAYPLUS_SANDBOX`.
כאן עובר כסף אמיתי — הכלי אומר את זה במפורש כשהוא מזהה שהוא מופנה
לשם.

## מה שאפשר לשלוח לי, ומה שלא

| אפשר | לא |
|---|---|
| הפלט של בדיקת העשן | `api-key`, `secret-key` |
| תשובות PayPlus למכתב | מפתח Supabase מסוג service role |
| `payment_page_uid`, `terminal_uid` | מפתח Resend |
| דוגמה של גוף הודעה חוזרת, בלי הטוקן | טוקנים של כרטיסים, מספרי כרטיס |
| הודעות שגיאה מהם | טוקנים של Cloudflare / Vercel |

`payment_page_uid` ו-`terminal_uid` הם מזהים ולא סודות — אבל גם
אותם עדיף פשוט להדביק ל-Vercel.
