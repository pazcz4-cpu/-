# המעטפת המקומית

זו הקליפה בלבד. **כל הקוד של המוצר יושב במאגר הראשי** —
`js/`, `css/`, `app.html` — והמעטפת עוטפת את הפלט של
`node build-site.js`. אין כאן עותק שני של המערכת, ולכן אין מה
לסנכרן ביד ואין שתי גרסאות שנפרדות בשקט.

## מה צריך כדי לבנות

| | iOS | Android |
|---|---|---|
| מחשב | **Mac** או שירות בנייה בענן | כל מחשב |
| כלי | Xcode | Android Studio / JDK |

**אין Mac? אל תקנה.** `Codemagic` ו-`Expo EAS` בונים, חותמים
ומעלים ל-App Store Connect בלי Mac באף שלב. Xcode Cloud אינו
פתרון לזה — מגדירים אותו מתוך Xcode, שהיא תוכנת macOS.
הפירוט: `docs/apple-setup.md`.

## הרצה מקומית

```
cd mobile
npm install
npx cap add ios        # פעם אחת, על Mac
npx cap add android    # פעם אחת
npm run sync           # בונה את האתר ומסנכרן לשתי הפלטפורמות
```

`npm run sync` מריץ את `build-site.js` של המאגר הראשי ואז
`cap sync`. **זו הפקודה היחידה שצריך אחרי כל שינוי בקוד.**

## מה המעטפת מוסיפה

אפל דוחה אפליקציה שהיא "אתר ארוז מחדש" (כלל 4.2). ארבעת אלה
הם מה שהופך אותה לאפליקציה, והם כולם כבר בקוד:

| | איפה |
|---|---|
| לשוניות תחתונות לפי תפקיד | `js/shell-ui.js` |
| פתיחה ביומטרית | `js/shell-ui.js` + `js/native.js` |
| התראות דחיפה | `js/native.js` |
| מסך שמסביר כשאין רשת | `js/shell-ui.js` |

הכול מזוהה בזמן ריצה, ולכן **אותו קוד רץ גם באתר** — שם כל
פונקציה נופלת בשקט להתנהגות הרגילה. אין מוצר שני לתחזק.

## בדיקה בלי לבנות

`?shell=1` מכריח את המעטפת בדפדפן:

```
npm run test:shell
```

זה מה שמאפשר לבדוק את הניווט המקומי בשניות במקום בסבב בנייה.

## מה אסור לשכוח

- **אפס רכישות בתוך האפליקציה**, ואפילו לא הפניה לרכישה בחוץ.
  `docs/app-stores.md`.
- **`appId` הוא לתמיד.** `com.setshifts.app` אינו ניתן לשינוי
  אחרי הפרסום הראשון.
- **לא לבנות מ-`site/`** שנוצר בסביבת פיתוח עם משתנים חסרים.
  הבנייה ל-חנות רצה עם אותם משתני סביבה של הפרודקשן.
