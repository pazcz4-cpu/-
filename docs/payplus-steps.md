# PayPlus — רשימת פעולות, בלי מונחים

שבע פעולות. כל אחת עומדת בפני עצמה. אין צורך להבין מה קורה
מאחורי הקלעים כדי לבצע אותן.

---

## 1 · להחליף את המפתחות  ← עכשיו

המפתחות הנוכחיים נחשפו. בלוח הבקרה של PayPlus, באזור שבו הם
מוצגים, יש אפשרות לייצר זוג חדש. מייצרים, והישן מתבטל.

**למה זה ראשון:** דרך המפתחות האלה אפשר לסלוק. זה לא תיאורטי.

את החדשים **לא שולחים לאף אחד** — הם הולכים ישר לשלב 5.

---

## 2 · לשלוח להם את המכתב

`docs/payplus-closing-letter.md` — מעתיקים ושולחים לתמיכה.

הוא מבקש מהם שלושה דברים שאי אפשר להתקדם בלעדיהם:

- שיקימו דף תשלום ייעודי ל-SetShifts
- כרטיסי בדיקה (מספר כרטיס שמצליח ואחד שנדחה)
- תשובה לשאלה אם טוקן שמור על מסוף אחד עובד על מסוף אחר

**השאלה השלישית היא הכי חשובה, וכדאי לדעת למה.** כשלקוח מזין
כרטיס אצלנו, PayPlus שומר "טוקן" — סוג של מפתח שמאפשר לנו לחייב
אותו כל חודש בלי שיזין כרטיס שוב. אם הטוקנים קשורים למסוף מסוים,
אז ביום שתעבור למסוף אחר כל הכרטיסים השמורים מפסיקים לעבוד, וכל
לקוח קיים צריך להיכנס ולהזין כרטיס מחדש.

אם התשובה שלהם היא "לא עובר בין מסופים" — בקש מהם מסוף ייעודי
כבר עכשיו, לפני הלקוח הראשון.

---

## 3 · לקבל מהם ארבעה ערכים

כשהם עונים, יהיו בידך ארבעה דברים. כולם מלוח הבקרה:

| השם | מה זה |
|---|---|
| `api-key` | מזהה החשבון מול המערכת שלהם |
| `secret-key` | הסוד שמלווה אותו |
| `payment_page_uid` | מזהה של דף התשלום שהם יקימו |
| `terminal_uid` | מזהה המסוף |

בשלב הזה **לא עושים איתם כלום**. הם נכנסים לשלב 5.

---

## 4 · בדיקה אחת, מהמחשב שלך

זו הפעולה היחידה ברשימה שדורשת טרמינל. אם אין לך נוחות עם זה —
**אפשר לדלג**, ובמקומה לבקש מהם תשובה בכתב לשאלה 4 במכתב. זה
שווה בדיוק אותו דבר.

מה זה עושה: פותח דף תשלום אמיתי בסביבת הבדיקות שלהם (לא בייצור,
לא עובר כסף), מדפיס את הכתובת, ובודק שהחיוב החודשי עובד.

```bash
git clone https://github.com/pazcz4-cpu/-.git setshifts
cd setshifts
git checkout claude/employee-shift-scheduling-n3lbhl

PAYPLUS_SANDBOX=true \
PAYPLUS_API_KEY='...' \
PAYPLUS_SECRET_KEY='...' \
PAYPLUS_PAYMENT_PAGE_UID='...' \
PAYPLUS_TERMINAL_UID='...' \
PUBLIC_BASE_URL=https://setshifts.com \
node tools/payplus-smoke.js
```

הכלי מדפיס כתובת. פותחים אותה בדפדפן, מזינים את כרטיס הבדיקה
שקיבלת, ואז מריצים שוב — אותה פקודה עם `--token=...` בסוף, כשהטוקן
נלקח ממסך העסקאות בלוח הבקרה.

**את הפלט של הכלי אפשר לשלוח לי.** הוא לא מכיל מפתחות: הם מודפסים
כאורך בלבד ולא כערך. זה מה שאני צריך כדי לסגור.

## 5 · להדביק את הערכים ב-Vercel

Vercel → הפרויקט → Settings → Environment Variables. מוסיפים
שורה לכל אחד:

| Name | Value |
|------|-------|
| `BILLING_PROVIDER` | `payplus` |
| `PAYPLUS_API_KEY` | מלוח הבקרה |
| `PAYPLUS_SECRET_KEY` | מלוח הבקרה |
| `PAYPLUS_TERMINAL_UID` | מלוח הבקרה |
| `PAYPLUS_PAYMENT_PAGE_UID` | מלוח הבקרה |
| `PUBLIC_BASE_URL` | `https://setshifts.com` |
| `CRON_SECRET` | מחרוזת אקראית שתמציא, כל דבר ארוך |
| `PAYPLUS_SANDBOX` | `true` |

**`PAYPLUS_READY` עדיין לא מוסיפים.** כל עוד הוא חסר, המערכת לא
מקבלת הודעות מ-PayPlus ולא מחייבת אף כרטיס — וזו בדיוק ההתנהגות
שרוצים לפני שהכל נבדק.

חוזרים על 4–6 עם מפתחות הייצור — **הם אינם אותם מפתחות** — ואז
מוחקים את `PAYPLUS_SANDBOX`. מהרגע הזה עובר כסף אמיתי. הכלי
בשלב 4 אומר את זה בקול אם מפנים אותו לשם.
