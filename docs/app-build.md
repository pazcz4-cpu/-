## ההתראות: מה עובד ומה חסום

**עובד כבר עכשיו:** האפליקציה מבקשת רשות, מקבלת אסימון
מכשיר, ושומרת אותו ב-`push_tokens` מול המשתמש והעסק. הטבלה
סגורה בפני המשתמש המחובר — אסימון שאפשר לקרוא הוא אסימון
שאפשר לשלוח בשמו הודעה למכשיר של אחר — והכתיבה היא דרך
`save_push_token` בלבד.

**חסום:** השליחה עצמה. היא דורשת מפתחות ששני חשבונות המפתח
מנפיקים, ואין דרך לעקוף:

| | מה צריך | מאיפה |
|---|---|---|
| iOS | **APNs Auth Key** (`.p8`) + Key ID + Team ID | חשבון Apple Developer |
| Android | קובץ `google-services.json` + חשבון שירות של Firebase | Firebase Console |

לכן השליחה תיבנה **אחרי** שהחשבונות ייפתחו — סביב 05/10,
כשה-D-U-N-S יגיע. אין טעם לכתוב אותה קודם: קוד שליחה שלא
נבדק מול ספק אמיתי הוא ניחוש.

**מה שיישלח, כשזה יעבוד:**

- "הסידור לשבוע הבא פורסם" — לעובדים שבו
- "בקשת החופשה אושרה" / "נדחתה" — למבקש בלבד
- "בקשה חדשה ממתינה לאישור" — למנהל

## הסדר מכאן

1. **עכשיו** — להחליט על שירות הבנייה. `codemagic.yaml` כבר
   כתוב; צריך רק לחבר את המאגר ולהגדיר שתי קבוצות משתנים.
2. **כשה-D-U-N-S מגיע** — לפתוח את שני חשבונות המפתח.
3. **מיד אחרי** — להנפיק APNs Key ולהקים פרויקט Firebase.
4. **ואז** — השליחה, ובדיקה על מכשיר אמיתי דרך TestFlight.

**לא מגישים לפרסום לפני TestFlight.** הסבב הראשון הוא היקר
ביותר, והוא זה שמגלה שהאפליקציה לא נפתחת או שההתחברות לא
עובדת מחוץ לישראל.

## מה שאסור לשכוח

- **סודות אינם נכנסים למאגר.** מפתחות החתימה, ה-APNs ו-Firebase
  מוגדרים בממשק של שירות הבנייה בלבד. אותו כלל שחל על מפתח
  Supabase ועל מפתח Resend.
- **`com.setshifts.app` הוא לתמיד.** מזהה החבילה אינו ניתן
  לשינוי אחרי הפרסום הראשון.
- **אפס רכישות בתוך האפליקציה**, ואפילו לא הפניה לרכישה בחוץ.
  `docs/app-stores.md`.
