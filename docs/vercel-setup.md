# למה שום דבר לא מתעדכן באתר, ואיך מסדרים

## מה קורה עכשיו

הקוד שלם ונדחף. בדקתי את הבנייה בתיקייה נקייה, בלי שום הגדרה,
והיא עוברת ומייצרת את הכל — את הסרטון, את `/admin/`, את תיקון
המע"מ.

**אבל Vercel מגיש גרסה ישנה ולא בונה מחדש.** לכן:
- הסרטון → 404
- `/admin/` → 404
- המע"מ → הנוסח הישן

**אחת מהבעיות הבאות**, וכולן במקום אחד:

1. פרויקט ה-Vercel **לא מחובר** לריפו ב-GitHub (הועלה פעם אחת
   מהמחשב). אז אף דחיפה לא תעדכן אותו, לעולם.
2. **Production Branch** מוגדר לענף שלא קיים.
3. **Auto-deploy כבוי.**

# חלק א · לגרום ל-Vercel לבנות מהקוד

## שלב 1 — להגיע למסך הנכון

1. להיכנס ל-**vercel.com** ולהתחבר.
2. בדף הראשי יש ריבועים של פרויקטים. **ללחוץ על הפרויקט של
   SetShifts.**
3. למעלה יש שורת לשוניות (Project / Deployments / Logs /
   **Settings** …). ללחוץ על **Settings**.
4. בתפריט הצדדי שנפתח, ללחוץ על **Git**.

## שלב 2 — מה כתוב שם

**מצב א׳: כתוב שאין ריפו מחובר**
(משהו בנוסח "No Git Repository connected", או שיש כפתור
"Connect Git Repository")

→ **זו הבעיה.** ללחוץ על הכפתור, לבחור GitHub, ולבחור את
`pazcz4-cpu/-`.

אם הריפו לא מופיע ברשימה, יש שם קישור בנוסח "Adjust GitHub App
Permissions" — ללחוץ עליו ולתת ל-Vercel גישה לריפו הזה.

**מצב ב׳: הריפו מחובר**

→ להסתכל מתחת, בשדה **Production Branch**. צריך להיות כתוב שם
בדיוק:

```
claude/employee-shift-scheduling-n3lbhl
```

אם כתוב משהו אחר (למשל `main`) — לשנות לזה ולשמור.

## שלב 3 — לגרום לבנייה לרוץ

אחרי שחיברת או שינית, צריך לדחוף משהו כדי שבנייה תרוץ. תגיד לי
ואני אדחוף שינוי קטן — זה ייקח שנייה.

> **שים לב:** כפתור **Redeploy** במסך Deployments בונה מחדש את
> **אותו קומיט ישן**, ולא את הקוד החדש. לכן הוא לא יעזור כאן.

## שלב 4 — לוודא שזה עבד

לפתוח בדפדפן:

```
https://setshifts.com/version.txt
```

**אם מופיע טקסט** עם `commit:` ו-`admin: כן` — הצלחנו. אפשר
להמשיך לחלק ב׳.

**אם 404** — הבנייה עדיין לא רצה. שלח לי צילום מסך של
Settings → Git ואגיד בדיוק מה לשנות.

# חלק ב · לפתוח את המשרד האחורי

**רק אחרי שחלק א׳ הצליח.**

## שלב 1 — חשבון

אם עוד אין לך חשבון במערכת: להיכנס ל-`https://setshifts.com/app/`
ולהירשם רגיל, עם `pazcz4@gmail.com`.

זה אותו חשבון שישמש גם למשרד האחורי. **אין סיסמה נפרדת** — יש
סוד אחד, וזה הנכון: סיסמה נוספת היא עוד סוד לשמור.

## שלב 2 — להגיד למערכת שאתה הבעלים

1. **vercel.com** → הפרויקט → **Settings**.
2. בתפריט הצדדי: **Environment Variables**.
3. למלא שתי משבצות:

   | משבצת | מה לכתוב |
   |---|---|
   | Key (או Name) | `PLATFORM_OWNER_EMAILS` |
   | Value | `pazcz4@gmail.com` |

4. מתחת יש בחירה של סביבות — **Production**, Preview,
   Development. לוודא ש-**Production מסומן**.
5. ללחוץ **Save**.

## שלב 3 — לבנות מחדש

משתנה סביבה חדש **לא נכנס לתוקף לבד**. צריך בנייה חדשה:
**Deployments** → הפריסה העליונה → תפריט שלוש הנקודות (`⋯`) →
**Redeploy**.

*(כאן Redeploy כן מתאים — הקוד כבר נכון, רק המשתנה חדש.)*

## שלב 4 — להיכנס

```
https://setshifts.com/admin/
```

מייל וסיסמה — אותם של החשבון משלב 1.

|---|---|
| `404 NOT_FOUND` | הבנייה לא רצה. חזרה לחלק א׳. |

# חלק ג׳ — שליחת פרטי כניסה לעובדים

## מה זה עושה

בכרטיס של כל עובד יש כפתור **"שליחת פרטי כניסה"**, ובעמוד
המשתמשים אפשר לשלוח **לכל העובדים הפעילים בלחיצה אחת**. מי שמקבל
את המייל מקבל בו:

- קישור למערכת
- שם משתמש (המייל שלו)
- סיסמה שהמערכת הגרילה עבורו
- הוראות איך להוסיף את המערכת למסך הבית באייפון ובאנדרואיד

הסיסמה נוצרת בשרת ונשלחת ישירות לעובד. היא אינה מוצגת לך ואינה
עוברת דרך הדפדפן שלך — כך אין מה להעביר בוואטסאפ ואין צילום מסך
עם סיסמה שנשאר בטלפון.

## שלב 1 — חשבון Resend

1. [resend.com](https://resend.com) → הרשמה (יש שכבה חינמית).
2. **Domains** → הוספת `setshifts.com` → להוסיף את רשומות ה-DNS
   שהוא נותן ב-Cloudflare → להמתין ל-Verified.
3. **API Keys** → Create API Key → הרשאת **Sending access**.

את המפתח מעתיקים ישירות מ-Resend אל Vercel. הוא לא צריך לעבור
בצ׳אט, בקובץ או בהודעה.

## שלב 2 — שלושה משתני סביבה ב-Vercel

Project → **Settings** → **Environment Variables**. שלושתם
ל-Production, Preview ו-Development:

| Key | Value | חובה? |
|---|---|---|
| `RESEND_API_KEY` | המפתח מ-Resend | כן |
| `MAIL_FROM` | `SetShifts <no-reply@setshifts.com>` | כן |
| `MAIL_REPLY_TO` | לאן ילכו תשובות של עובדים | לא |
| `CONTACT_TO` | לאן מגיעות פניות מטופס "צור קשר" | לא** |
| `APP_URL` | `https://www.setshifts.com/app/` | לא* |

\*\* ברירת המחדל היא `support@setshifts.com`. הגדירו אותו רק אם
פניות מהאתר צריכות להגיע לתיבה אחרת מקריאות השירות. תשובה לפנייה
כזו חוזרת אל מי שפנה ולא אלינו, בלי קשר למה שמוגדר ב-`MAIL_REPLY_TO`.

\* בלעדיו הקישור במייל נגזר מהדומיין שממנו רצה הבקשה, וזה נכון
ברוב המקרים. כדאי להגדיר אותו כדי שגם מייל שנשלח מסביבת Preview
יפנה לאתר האמיתי.

**הכתובת ב-`MAIL_FROM` חייבת להיות בדומיין שאומת ב-Resend.**
כתובת שלא אומתה מוחזרת עם `domain not verified`, והמסך יגיד
"החשבון מוכן אבל המייל לא נשלח".

## שלב 3 — Redeploy

Deployments → הפריסה העליונה → ⋯ → **Redeploy**.

## שלב 4 — לבדוק

בכרטיס עובד אחד (עם המייל שלך בתוכו) → "שליחת פרטי כניסה".
מה שאמור לקרות: הודעה "נשלחו פרטי כניסה אל…", ומייל אצלך תוך
שניות. אם הוא לא הגיע — Resend → **Logs** מראה כל בקשה ומה קרה
לה.

## מה אומרת כל שגיאה

| מה רואים | מה זה אומר |
|---|---|
| "שליחת פרטי כניסה אינה מוגדרת" | `RESEND_API_KEY` או `MAIL_FROM` חסרים, או שלא נבנה מחדש |
| "החשבון מוכן אבל המייל לא נשלח" | Resend דחה: לרוב דומיין שלא אומת ב-`MAIL_FROM` |
| "כתובת המייל כבר משויכת לחשבון אחר" | הכתובת רשומה כבר בעסק אחר במערכת |
| "הבעלים קובע סיסמה בעצמו" | אי אפשר לאפס מכאן את הסיסמה של בעל החשבון — רק דרך "שכחתי סיסמה" |
