## 1 · המסלול הקריטי: מסליקה ללקוח הראשון

```
בנק ✅ → ספק סליקה (ישראכרט) → PayPlus → בדיקה ב-sandbox → ייצור → לקוח ראשון
```

### 1.1 ספק סליקה (ישראכרט)
- **סטטוס:** ⬜ פתוח אצלך, שבוע הבא
- **חוסם:** PayPlus, ולכן את הלקוח הראשון
- **מה להכין:** אישור ניהול חשבון מהבנק, תעודת התאגדות, ת.ז. של החותם בשם החברה, ואתר פעיל. הרשימה המדויקת: לבקש מהנציג בכתב.
- **מה האתר כבר מראה:** תנאי שימוש עם מדיניות ביטול, פרטיות, אבטחה, נגישות ועמוד מחירים.
- **שאלה לשאול כבר בפנייה הראשונה:** האם המסוף מאושר לחיוב חוזר (מנוי חודשי) בלי נוכחות הלקוח.
- **מלכודת:** פרטי העסק באתר חייבים להיות זהים למסמכי הבנק והחברה (2.7).

### 1.2 PayPlus
- **סטטוס:** ⏳ אחרי 1.1. המדריך המלא: `docs/payplus-steps.md`
- **חוסם:** הלקוח הראשון
- **צעדים:**
  1. מפתחות חדשים. הנוכחיים נחשפו בשיחה. מחליפים מיד גם באתר המכירות של החברה השנייה, כדי שהסליקה שם לא תיפול.
  2. לשלוח לתמיכה את `docs/payplus-closing-letter.md`.
  3. לקבל ארבעה ערכים: `api-key`, `secret-key`, `payment_page_uid`, `terminal_uid`. מדביקים ישר ב-Vercel, לא בצ'אט.
  4. בדיקת sandbox אחת עם `tools/payplus-smoke.js`. את הפלט אפשר לשלוח לי, הוא לא מכיל מפתחות.
  5. ב-Vercel: `BILLING_PROVIDER=payplus`, ארבעת הערכים, `PUBLIC_BASE_URL=https://setshifts.com`, `CRON_SECRET`, `PAYPLUS_SANDBOX=true`.
  6. אחרי שהבדיקה עברה: `PAYPLUS_READY=true`.
  7. ייצור: מפתחות ייצור (אחרים), ומוחקים `PAYPLUS_SANDBOX`. מכאן עובר כסף אמיתי.
- **מלכודת:** אם טוקן שמור אינו עובר בין מסופים, צריך מסוף ייעודי לפני הלקוח הראשון.
